# بروتوكول الغرفة المحلية لطرنيب

## المبدأ

يكون هاتف المنشئ هو **المضيف والحكم الوحيد** للمباراة. تتصل ثلاثة هواتف أخرى به عبر TCP داخل الشبكة المحلية نفسها. لا يثق المضيف في أي حالة مرسلة من العميل؛ لذلك لا يمكن للعميل توزيع أوراق أو إعلان فائز أو تعديل النقاط.

## تغليف الرسائل

كل رسالة JSON مفردة ومنتهية بحرف سطر جديد، ويجب أن تحتوي على `version` و`id` و`type` و`roomId`. يرفض المضيف الرسائل التي تتجاوز الحجم المسموح أو لا تطابق النسخة أو رمز الانضمام.

| النوع | الاتجاه | الغرض |
|---|---|---|
| `hello` | عميل ← مضيف | تقديم اسم العرض ورمز الجلسة وطلب مقعد |
| `joined` | مضيف ← عميل | تأكيد المعرف والمقعد وملخص أعضاء الغرفة |
| `room_snapshot` | مضيف ← الجميع | تحديث مقاعد الغرفة والجاهزية قبل البدء |
| `intent` | عميل ← مضيف | نية اللاعب: جاهز أو مزايدة أو اختيار طرنيب أو لعب ورقة |
| `state_snapshot` | مضيف ← عميل | لقطة مباراة مفلترة للمقعد المتلقي |
| `error` | مضيف ← عميل | رفض مفهوم وقابل للعرض، مثل ورقة غير قانونية أو غرفة مكتملة |
| `ping` / `pong` | ثنائي الاتجاه | إبقاء الاتصال واكتشاف الانقطاع |

## الخصوصية والموثوقية

يتلقى كل لاعب يده فقط، بينما تتلقى بقية المقاعد عدد أوراق الخصوم ولا تظهر وجوهها. يربط المضيف كل اتصال بمقعد واحد ورمز عشوائي قصير العمر. لا تعرض واجهة QR رمزًا ثابتًا أو بيانات مباراة محفوظة. يُقبل اتصال جديد عند امتلاء الغرفة فقط عندما يكون رمز إعادة الاتصال صحيحًا للمقعد السابق.

## نطاق النسخة الأولى

تبدأ الغرفة بأربعة لاعبين بشريين ومضيف واحد. لا تدعم النسخة الأولى دخول لاعب آلي إلى غرفة الشبكة، أو نقل الاستضافة، أو اللعب بين شبكات مختلفة. يبقى اللعب الفردي الحالي ضد الخصوم الآليين كما هو.

## الاكتشاف المحلي الاختياري

ينشر المضيف خدمة `tarneeb._tcp.local.` باسم غرفة قصير ورقم منفذ TCP، ويضع في سجل TXT رقم إصدار البروتوكول ومعرف الغرفة فقط؛ ولا ينشر رمز الجلسة أو أي أوراق. يبحث العميل عن الخدمة نفسها ثم يعرض الغرف المحلولة التي تحمل النسخة المدعومة. يظل QR هو مسار الانضمام الأساسي والبديل، لأن اكتشاف mDNS قد تحجبه بعض الشبكات.

على iOS يجب تعريف `NSLocalNetworkUsageDescription` وخدمة `NSBonjourServices` المطابقة. وعلى Android يلزم الوصول إلى حالة الشبكة وWi‑Fi وإذن تغيير حالة multicast. تستخدم طبقة الاكتشاف تنفيذ DNSSD في الإنتاج على Android لرفع التوافق بين الإصدارات والأجهزة.[1]
