# السبب الجذري لاختلاف واجهة المزايدة في APK

**التاريخ:** 20 أغسطس 2026  
**المنصة المتأثرة:** Android الأصلي، وبالأخص الشاشات قصيرة الارتفاع مثل Redmi 14C.

## الخلاصة

المشكلة **ليست** ناتجة عن حذف NativeWind أو تنظيف CSS في بناء Android. عناصر المزايدة ومروحة الأوراق في `app/(tabs)/index.tsx` تستعمل `StyleSheet.create()` وأنماط React Native صريحة، وهذه لا تمر عبر تنقية CSS الخاصة بالويب.

السبب الجذري هو فرق نموذج التخطيط: معاينة الويب تملك وثيقة HTML وشريطًا سفليًا مختلفًا، بينما APK يطبق مساحات Android الآمنة وشريط التبويب الأصلي ضمن ارتفاع الشاشة الحقيقي. كانت الشاشة قابلة للتأثر بأمرين متداخلين: حجز الحافة السفلية مرتين في مسار قديم، وعدم ربط `ScrollView` في شاشة المزايدة صراحةً بارتفاع الحاوية الأصلية. النتيجة على الشاشة القصيرة هي أن أسفل المحتوى — مروحة اليد أو شبكة أرقام المزايدة — قد يُقصّ بصريًا أو لا يحصل على مساحة تمرير كافية.

| العنصر | المعاينة على الويب | APK الأصلي | الإصلاح الحالي |
|---|---|---|---|
| المساحة السفلية | لا تعتمد على Android inset | تعتمد على `insets.bottom` وشريط تبويب | حافة SafeArea السفلية لا تُطبّق مرتين |
| حاوية المزايدة | مساحة المتصفح مرنة | تحتاج ارتفاعًا محدودًا صريحًا | `formScroll: { flex: 1 }` |
| محتوى التمرير | يتوسع حسب صفحة الويب | قد يضغط تحت عناصر النظام | `scrollContent: { flexGrow: 1 }` |
| المظهر | CSS وDOM | StyleSheet وYoga layout | لا يعتمد على NativeWind لهذه العناصر |

## الإصلاح الذي طُبّق

تستخدم شاشة المزايدة الآن `ScrollView` مرتبطة بحاويتها عبر `styles.formScroll`، بينما يسمح `styles.scrollContent` بالتمدد. ويستمر الاحتفاظ بـ `paddingBottom: insets.bottom + 34` للمحتوى، مع اقتصار `SafeAreaView` على الحواف العلوية والجانبية. هذا يمنع مضاعفة حجز المنطقة السفلية ويسمح بالوصول إلى شبكة الأرقام ومروحة اليد حتى على الارتفاعات الضيقة.

## لماذا قد تبدو المشكلة موجودة بعد الإصلاح

لا يظهر هذا التعديل في هاتف عليه APK قديم. يلزم إنشاء APK جديد وتثبيته فوق النسخة السابقة أو بعد حذفها. كما أن تعلّق عملية البناء عند 1% يعني عدم توفر حزمة Android جديدة أصلًا للتحقق من التغيير؛ لذلك سيستمر الهاتف بعرض سلوك البناء السابق إلى أن ينجح بناء جديد.

## التحقق الآلي

أضيف اختبار `bidding-layout-android.test.ts` يثبت أن شاشة المزايدة تملك `flex: 1` لحاوية التمرير و`flexGrow: 1` للمحتوى، إلى جانب اختبارات المساحات الآمنة لـ Redmi 14C. اجتازت النسخة 72 اختبارًا، مع اختبار واحد متخطى عمدًا، إضافة إلى فحص TypeScript وExpo ESLint.
